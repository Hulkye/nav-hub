# NavHub Admin

基于官方 [Nuxt UI Dashboard 模板](https://github.com/nuxt-ui-templates/dashboard) 创建，保留 [MIT 许可证](./LICENSE)。

管理台独立于前台构建，访问路径为 `/admin/`。模板的应用入口、Dashboard 布局、侧栏搜索、用户菜单、颜色模式和 Tailwind 样式结构用于 NavHub 管理业务；示例邮件、客户、设置及模拟 API 已移除。

列表界面对齐官方 `app/pages/customers.vue`：新增按钮置于 Dashboard Navbar 右侧；主体采用搜索与筛选工具栏、列显示菜单、`UTable`、行操作菜单，底部显示记录数量和分页。网站及内容列表支持多选和批量状态操作。分类与标签通过导航工具栏标签页切换。共享 `AdminTable` 统一使用官方模板的表头、单元格边框及底部分页样式；服务端分页仍由业务 API 驱动。

空状态统一由自绘 `AdminEmpty` 呈现：纸页插画、克制的轨道与微光动效，配合情境化标题和短说明，不放置操作按钮。尊重减少动态效果偏好；表格加载中使用骨架屏。

新增与编辑页面对齐官方 Settings 页面：居中 `lg:max-w-2xl` 表单，顶部使用横向裸 `UPageCard` 展示标题、说明和保存操作，字段置于 `variant="subtle"` 卡片中，以说明文字和 `USeparator` 分隔。桌面端标签说明与控件左右排列，小屏上下排列；正文等长文本使用全宽输入。保存与保存并发布仍调用现有业务接口。

网站、资源、媒体、文章、公告进入模块后展示分页列表。新增进入对应的 `/<模块>/update` 页面，编辑使用同一页面并携带 `?id=<记录 ID>`，保存后返回列表。分类与标签分别分页；共用 `/categories/update`，标签操作携带 `kind=tags`。分类与标签当前使用客户端分页，其余内容模块使用服务端分页。选择器的“全部”和“无父分类”等选项使用非空值，在提交查询或保存时转换为省略参数或 `null`。

全局设置 `/admin/settings` 为功能入口，以卡片展示品牌与页脚、主导航、主题、网站卡片、搜索源、内置文案覆盖、移动端底部导航和默认 SEO。各功能使用 `/admin/settings/<功能>` 独立二级页面，提供返回入口与保存操作。保存前重新读取配置，仅合并当前功能的字段后执行完整校验，避免用旧表单覆盖其他功能的已保存配置。

在仓库根目录运行 `npm install`、`npm run dev`，访问 `http://localhost:3000/admin/login`。API 由独立的 `../api/` 提供，数据库只由 API 服务访问。完整运行与部署说明见 [开发文档](../doc/DEVELOPMENT_PLAN.md#本地运行)。
