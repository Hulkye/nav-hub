### 定时链接检查

执行 `npm run links:check` 可运行一次受控巡检：仅检查已发布网站/资源，跳过忽略项及 24 小时内已检查内容，按最久未检查顺序单次最多 100 项，逐项复用现有 SSRF 防护和超时限制。运行摘要写入数据库；后台链接检查页显示失败提醒与最近定时运行结果。失败链接由管理员修正、重试、下线或忽略，不自动删除或下线。

生产通过主机 cron、systemd timer 或编排器 CronJob 调用此命令，例如每小时一次；进程须设置 `DATABASE_URL` 和项目工作目录。任务使用专用数据库连接持有 advisory lock，多个副本同时调用只允许一个定时任务运行；异常退出释放锁，下次运行把遗留运行标为失败，并继续选择仍过期的目标。需要离站提醒时，将命令标准错误接入已有日志告警系统，目前不发送邮件、短信或 webhook。手动检查仍使用现有进程内队列，其跨副本队列分发不属于本次变更。

数据库迁移在内嵌 PostgreSQL 测试引擎验证，不等同于真实生产迁移和恢复演练。真实 S3/MinIO、联合备份恢复、外链网络检查及生产定时器须按部署环境验收。

图片对象联合备份与恢复流程：

1. 暂停后台写操作和图片删除，在同一维护窗口备份 PostgreSQL，并用 MinIO `mc mirror` 或存储提供商的备份工具复制完整桶。记录桶名、备份时间和数据库备份文件，不把访问密钥写入报告。仅复制数据库不能恢复图片。

4. 打开恢复站点抽查图标、封面和正文图片；确认引用图片不能删除、未引用图片可以删除、删除不会影响生产桶。记录结果后才结束演练。当前尚未在真实对象存储完成此演练。

## 本地运行

项目使用 npm workspaces 拆分为三个独立应用：

- `app/`：前台 Nuxt 应用，不依赖 Nuxt UI。
- `admin/`：使用 `npm create nuxt@latest admin -- -t gh:nuxt-ui-templates/dashboard --no-install --no-gitInit --packageManager npm` 创建的独立管理台；保留官方模板许可证，并将示例业务替换为 NavHub 内容管理功能。管理台使用 `/admin/` 作为 base URL。
- `api/`：独立 API 服务，统一维护公开与管理接口、数据库访问、会话和审核逻辑。`shared/` 提供共用 schema 与类型，`db/` 保留迁移与数据库 schema。

在根目录执行 `npm install` 后，`npm run dev` 同时启动前台（3000）、管理台（3001）和 API（3002）。统一访问 `http://localhost:3000` 和 `http://localhost:3000/admin/login`；前台将 `/admin/**` 转发至管理台、`/api/**` 转发至 API，因此浏览器保持同源 Cookie 和 Origin 校验。SSR 请求也通过相同代理访问 API。

管理台开发热更新通过前台 Nitro `devProxy` 转发 `/admin/_nuxt/` WebSocket，HMR 客户端端口使用统一入口 3000。Vite 自动附加 `/admin/_nuxt/` 基路径，因此 `hmr.path` 仅设置 `/`，避免重复路径。修改本地入口端口或使用 HTTPS 开发代理时，需同步调整管理台 HMR 的端口和协议。生产代理与构建不依赖此开发配置。

`npm run build`、`npm run typecheck` 分别构建、检查全部工作区；`npm start` 同时启动三个生产服务。单独运行可使用 `npm run dev --workspace @navhub/app`、`@navhub/admin` 或 `@navhub/api`。生产代理目标在构建时读取 `API_ORIGIN`、`ADMIN_ORIGIN`；容器内三个进程默认通过回环地址互通。只有 API 服务读取 `DATABASE_URL`。数据库迁移、管理员初始化和测试命令仍从根目录运行。

1. 使用 Node.js 24，执行 `npm install`。
2. 从 `.env.example` 复制 `.env`，设置 `POSTGRES_PASSWORD`，同步填写 `DATABASE_URL`（密码中的特殊字符需 URL 编码）。
3. 安装 Docker 后执行 `docker compose up -d postgres`，或直接连接已有 PostgreSQL。
4. 执行 `npm run db:migrate`；迁移通过事务和数据库锁串行执行，可重复运行。
5. 在本地受控环境设置 `ADMIN_USERNAME` 和至少 12 位的 `ADMIN_PASSWORD`，执行 `npm run admin:create`，随后移除初始化密码。没有默认管理员和默认密码。
6. 执行 `npm run dev`。访问 `/admin/login` 登录；生产运行 `npm run build`、`npm start`。

生产必须正确设置 `NUXT_PUBLIC_SITE_URL` 为公开 HTTPS 地址；它用于写请求 Origin 校验及 Secure Cookie 设置。会话随机令牌仅以哈希存入数据库，8 小时到期，退出立即撤销；无需 SESSION_SECRET。数据库连接仅服务端可用。登录限流按服务端连接 IP，每 15 分钟最多 5 次；代理部署需另行配置可信代理和边缘限流策略。过期会话及限流记录清理任务放在生产化阶段。部署探针：`GET /api/health/live` 检查进程响应，`GET /api/health/ready` 检查数据库可用性；建议编排器用 readiness 决定是否接流量，用 liveness 发现进程失效，且不要将探针暴露给不受信任的外部监控方。

## 验证

`npm test` 使用内嵌 PostgreSQL 引擎 PGlite 验证迁移、密码、会话过期/撤销和数据库限流；`npm run typecheck` 检查类型；`npm run build` 检查生产产物。PGlite 测试不替代正式 PostgreSQL 的部署验收。

早期基础骨架验收曾验证首页及登录页 SSR、管理台 noindex、未登录管理 API 返回 401、管理页登录跳转及跨来源登录请求返回 403。当前回归和环境状态以上文本批验证为准；本地检查不替代正式部署、真实对象存储和完整浏览器登录/退出验收。
